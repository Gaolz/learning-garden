# 每日算法：选择排序 (Selection Sort)

> **一句话总结：** 每次从未排序区间里"选"出最小的那个元素，扔到已排序区间的末尾——像排队时每次都把最矮的人拉到队伍最前面。

---

### 1. 🎯 解决的核心问题

* **现实痛点：** 给你一堆杂乱无章的数字，要怎么从头排到尾？最朴素的想法就是：我从头看到尾，找出最小的放第一位；再从剩下的里面找最小的放第二位……这就是选择排序，是你能想到的"最暴力、最直觉"的排序方式。
* **应用场景：**
  * 对极其简单的嵌入式设备或内存极度受限的场景（代码短小、原地排序）。
  * 当"交换次数"必须最少时（每轮最多只交换 1 次）。
  * 教学场景——它是理解排序算法思维的"第一块砖"。

---

### 2. 📊 复杂度与优缺点

| 维度 | 指标 / 特性 | 补充说明 |
| :--- | :--- | :--- |
| **时间复杂度（平均）** | $O(n^2)$ | 无论数据怎样，都要做 $\frac{n(n-1)}{2}$ 次比较 |
| **时间复杂度（最坏）** | $O(n^2)$ | 即使已排好序，选择排序也不会提前收工 |
| **空间复杂度** | $O(1)$ | 原地 (In-place) 排序，只用几个临时变量 |
| **稳定性** | 不稳定 | 交换可能把相同值元素的相对顺序打乱 |

* **优点：**
  * 实现极其简单，代码量最少。
  * 交换次数为 $O(n)$，是所有比较排序中最少的——当交换成本远高于比较成本时有优势。
* **缺点：**
  * 无论数据如何，都是硬邦邦的 $O(n^2)$，不具备任何"提前终止"或"利用局部有序"的能力。
  * 对大规模数据完全不可用。

---

### 3. 🎨 算法示意图 (Diagram)

```
初始数组: [ 64  25  12  22  11 ]

Round 1: 在 [64 25 12 22 11] 中找最小 → 11 (index 4), 与 index 0 交换
          ┌──────────────────────────────┐
          ↓                              ↓
          [ 11 | 25  12  22  64 ]
            ↑           ↑
          sorted    unsorted

Round 2: 在 [25 12 22 64] 中找最小 → 12 (index 2), 与 index 1 交换
          ┌─────────────────┐
          ↓                 ↓
          [ 11  12 | 25  22  64 ]

Round 3: 在 [25 22 64] 中找最小 → 22 (index 3), 与 index 2 交换
          ┌──────────┐
          ↓          ↓
          [ 11  12  22 | 25  64 ]

Round 4: 在 [25 64] 中找最小 → 25 (index 3), 已经在正确位置，自交换
          [ 11  12  22  25 | 64 ]

Done:    [ 11  12  22  25  64 ]
```

**逻辑推演步骤：**
1. **Step 1:** 外层指针 `i` 从 0 走到 n-1，表示"下一个要填充的位置"。
2. **Step 2:** 内层循环从 `i+1` 走到 n-1，找出这轮的最小值下标 `min_idx`。
3. **Step 3:** 把 `arr[min_idx]` 和 `arr[i]` 交换——这轮最小元素"落位"。
4. **Step 4:** `i++`，重复直到最后一个元素自动就位。

### 4. 💻 代码实现 (Ruby & Rust)

#### 💎 Ruby 实现（注重表达力与优雅）

```ruby
def selection_sort(arr)
  n = arr.length
  (0...n).each do |i|
    # 假设当前位置就是最小的
    min_idx = i

    # 在未排序区域中寻找真正的最小值
    (i + 1...n).each do |j|
      min_idx = j if arr[j] < arr[min_idx]
    end

    # 将找到的最小值与当前位置交换（Ruby 的平行赋值一行搞定）
    arr[i], arr[min_idx] = arr[min_idx], arr[i] if min_idx != i
  end
  arr
end

# --- 测试 ---
puts selection_sort([64, 25, 12, 22, 11]).inspect
# => [11, 12, 22, 25, 64]
```

#### 🦀 Rust 实现（注重所有权、类型安全与内存效率）

```rust
/// 选择排序（原地排序，O(n²)）
///
/// 要求 T 实现 `Ord` 可比较、`Copy` 可在栈上复制（避免所有权转移的复杂性）
pub fn selection_sort<T: Ord + Copy>(arr: &mut [T]) {
    let n = arr.len();
    // 外层：逐个确定每个位置该放谁
    for i in 0..n {
        let mut min_idx = i;
        // 内层：在未排序区间 [i+1, n) 中找最小元素的下标
        for j in (i + 1)..n {
            if arr[j] < arr[min_idx] {
                min_idx = j;
            }
        }
        // 若最小值不在当前位置，则交换
        if min_idx != i {
            arr.swap(i, min_idx); // `swap` 是切片方法，安全且无所有权问题
        }
    }
}

fn main() {
    let mut data = vec![64, 25, 12, 22, 11];
    selection_sort(&mut data);
    println!("{:?}", data); // [11, 12, 22, 25, 64]

    // 泛型同样适用于字符切片
    let mut chars = vec!['d', 'a', 'c', 'b'];
    selection_sort(&mut chars);
    println!("{:?}", chars); // ['a', 'b', 'c', 'd']
}
```

### 5. 💡 Ruby vs Rust 编程体会

**Ruby 视角的思考：**
Ruby 的 `a, b = b, a` 平行赋值语法让元素交换不用引入临时变量，代码读起来像伪代码一样顺畅。`(0...n).each` 配合 Range 的语义很自然。你可以快速把脑中的算法逻辑"翻译"成代码原型，几乎零阻力。但代价是 Ruby 没有编译期类型检查——传错了类型只能在运行时爆。

**Rust 视角的思考：**
Rust 用 `T: Ord + Copy` 明确声明了算法的"契约"：元素必须可比较且可复制。`arr.swap(i, min_idx)` 是切片的内建方法，底层是 `unsafe` 的 `ptr::swap` 但对外暴露的安全接口——这正是 Rust 的哲学：把"不安全"锁在标准库内部，让使用者在安全边界内写代码。`&mut [T]` 意味着"我独占这段内存的可变引用"，编译器会阻止你同时读写同一段数据，从根本上消灭了数据竞争。

**两者的碰撞：** Ruby 让你 5 分钟写出原型，牺牲了运行时安全换来表达力；Rust 让你写的时候多想了 5 分钟，但换来了零抽象成本的运行效率和内存安全保证。选择排序的简单逻辑在两种语言中都是几行代码，但底层哲学天差地别——一个是"相信程序员"，一个是"编译器替你审核"。

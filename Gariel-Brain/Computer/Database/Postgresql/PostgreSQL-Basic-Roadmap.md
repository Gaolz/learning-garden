# PostgreSQL 基础与核心功能 Roadmap

这份 Roadmap 专为 PostgreSQL 初学者与应用开发者设计，涵盖了除基础 CRUD（`SELECT`, `INSERT`, `UPDATE`, `DELETE`）之外，在实际业务开发中最常使用、最关键的 **PostgreSQL 原生核心功能**。

```
[Level 1: 核心基础] ──> [Level 2: 进阶建模与约束] ──> [Level 3: 高级查询与计算] ──> [Level 4: 性能与事务控制]
```

---

## 🟢 Level 1：核心基础（高效查询与数据组织）

> **特点**：超越基础 SQL，提升日常开发效率与数据处理灵活性。

| 特性/功能名称 | 难易度 | 简介与核心用途 |
| :--- | :---: | :--- |
| **基础聚合与分组 (GROUP BY & HAVING)** | ⭐ | **简介**：对数据进行分组统计与二次过滤（如 `COUNT`, `SUM`, `AVG`）。<br>**用途**：生成业务报表、统计用户数量、计算平均客单价等。 |
| **常用内置函数 (Dates, Strings, Arrays)** | ⭐ | **简介**：PG 丰富的时间/字符串处理函数及原生数组类型（Array）。<br>**用途**：处理时区转换（`AT TIME ZONE`）、格式化时间、使用标签/数组字段避免建中间关联表。 |
| **视图 (Views)** | ⭐ | **简介**：将复杂查询保存为虚拟表，封装查询逻辑。<br>**用途**：简化前端或下游系统的查询复杂度、进行敏感字段的权限隔离展示。 |

---

## 🟡 Level 2：进阶建模与约束（数据完整性与高级数据类型）

> **特点**：利用 PG 强大的数据校验机制，从源头保证数据规范与健壮性。

| 特性/功能名称 | 难易度 | 简介与核心用途 |
| :--- | :---: | :--- |
| **高级约束 (CHECK & EXCLUDE)** | ⭐⭐ | **简介**：在表结构层面直接校验字段范围或阻止特定逻辑重叠。<br>**用途**：限制 `age > 0`、校验枚举值，或使用排他约束（EXCLUDE）防止会议室预约时间重叠。 |
| **自增主键与序列 (IDENTITY & SEQUENCE)** | ⭐⭐ | **简介**：标准的自增列控制机制与序列生成器。<br>**用途**：生成唯一 ID、按特定规则生成订单流水号。 |
| **枚举类型 (ENUM Types)** | ⭐⭐ | **简介**：自定义有限范围的命名枚举类型。<br>**用途**：限定订单状态（`pending`, `paid`, `shipped`），提升代码可读性与数据安全性。 |

---

## 🟠 Level 3：高级查询与计算（复杂业务逻辑处理）

> **特点**：将原本需要在后端代码中循环处理的逻辑，高效移交给数据库层完成。

| 特性/功能名称 | 难易度 | 简介与核心用途 |
| :--- | :---: | :--- |
| **窗口函数 (Window Functions)** | ⭐⭐⭐ | **简介**：在不改变结果行数的情况下，计算跨行数据（如 `ROW_NUMBER()`, `RANK()`, `LEAD()`, `LAG()`）。<br>**用途**：计算排行榜、分组取 Top N、计算同比/环比增长率。 |
| **通用表表达式 (CTE / WITH 语句)** | ⭐⭐⭐ | **简介**：将复杂 SQL 模块化拆分，以及支持递归查询（`WITH RECURSIVE`）。<br>**用途**：提升复杂 SQL 可读性，以及查询组织架构树、多级分类菜单等层级数据。 |
| **物化视图 (Materialized Views)** | ⭐⭐⭐ | **简介**：将复杂查询的结果持久化存储到磁盘，并支持异步刷新。<br>**用途**：缓存耗时的报表计算，将秒级/分钟级的复杂分析查询降低到毫秒级。 |
| **Upsert (ON CONFLICT)** | ⭐⭐⭐ | **简介**：插入数据时，遇到主键或唯一约束冲突自动转换为更新。<br>**用途**：实现“存在即更新，不存在即插入”的幂等写入逻辑（如计数器累加、同步第三方数据）。 |

---

## 🔴 Level 4：性能优化与事务控制（生产环境硬核能力）

> **特点**：涉及高效的事务控制、自定义逻辑封装与索引调优。

| 特性/功能名称 | 难易度 | 简介与核心用途 |
| :--- | :---: | :--- |
| **事务与保存点 (TRANSACTION & SAVEPOINT)** | ⭐⭐⭐⭐ | **简介**：保证多条 SQL 执行的原子性（ACID），以及局部回滚机制。<br>**用途**：转账交易、多表联立更新，出现部分异常时优雅降级与回滚。 |
| **存储过程与触发器 (PL/pgSQL & Triggers)** | ⭐⭐⭐⭐ | **简介**：在数据库内部编写业务逻辑函数，以及在增删改时自动触发。 | **用途**：自动记录数据变更日志（Audit Log）、同步更新关联字段、实现复杂的库内业务校验。 |
| **索引策略 (B-Tree, Partial & Expression Index)** | ⭐⭐⭐⭐ | **简介**：PG 灵活的索引机制，包括条件索引（Partial Index）与表达式索引。<br>**用途**：仅对未处理数据建索引（`WHERE status = 'pending'`），或者对 `LOWER(email)` 建索引提升查询速度。 |

---

## 🎯 推荐的学习步骤

1. **第一站（窗口函数与 CTE）**：掌握 `OVER (PARTITION BY ...)` 与 `WITH` 语法，解决 80% 的复杂查询与报表需求。
2. **第二站（Upsert 与 CHECK 约束）**：掌握优雅的优雅数据写入与数据质量保障。
3. **第三站（触发器与物化视图）**：体验自动化数据审计与大表查询性能飞跃。
